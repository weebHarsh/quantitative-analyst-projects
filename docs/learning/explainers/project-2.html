Watching the booth live

Numbers: seeded bad-session demo (seed 7, 2 hours). Source: projects/02-risk-monitor/examples/demo_bad.txt

Project 1 reads the receipts at closing. This one watches live.

A manager cannot wait for closing time to learn the booth is in trouble. The monitor keeps the same numbers fresh while the day is still running.

A running tally must end at the closing total.

Adding each receipt as it arrives is fast. The check is that it never drifts from the slow way (incremental vs batch).

A trade's verdict arrives a second later, so the monitor keeps a waiting line.

Project 1 does the same, so the live numbers still match. A fill's one-second verdict (markout) is only knowable one second after it.

Four dials, each with a warn line and a breach line.

Fills a minute guards against a quiet booth and a booth being picked off. The markout floor guards against informed customers (adverse selection).

An alarm needs a reset gap, or it flaps.

Position warns at 60 and only clears below 40 (hysteresis). A cooldown then holds back repeats of the same or lower severity. A worse level always gets through.

Test it on a day built to go wrong.

Place each line above the worst good day, below the damage.

Lower the warn line and clean days start alarming. Raise the breach line and real damage goes unreported. These lines fit this simulator, so real flow needs fresh ones.
